### Bugs encontrados e corrigidos no script local
- **Parâmetro `$Args` colidia com a variável automática do PowerShell** (`$args`) — causava bagunça na passagem de argumentos pro `graphify`. Corrigido renomeando para `$CmdArgs`
- **`2>&1` + `$ErrorActionPreference="Stop"` em comando nativo (`git`)** — PowerShell 5.1 trata qualquer linha de stderr (mesmo informativa, como "From https://...") como erro fatal. Corrigido: removido `$ErrorActionPreference="Stop"`, e o sucesso passou a ser decidido só por `$LASTEXITCODE`
- **Mojibake de acentos no log** (`Área` → `ÃƒÂrea` → `Ãrea`) — PowerShell 5.1 decodifica saída de processo nativo não-interativo usando o codepage legado do console, e isso não é corrigível de forma confiável via `[Console]::OutputEncoding`/`$OutputEncoding` nesse cenário. Solução: sanitizar a saída pra ASCII antes de logar (`?` no lugar do caractere quebrado) — o log é só pra checagem rápida de pass/fail, os arquivos reais no vault foram verificados via `ls` e estão corretos

### Instalação do Open Design — decisão final: versão portátil isolada
- Rejeitado: instalador `.exe` do sistema (sem assinatura digital/Authenticode — comum em OSS mas gera aviso do SmartScreen) e Docker (quebraria a orquestração de CLI local — cairia em modo BYOK com API key paga em vez de usar a sessão Claude Code já logada).
- Escolhido: **versão portátil**, sem instalador, extraída em `C:\open-design-sandbox\app\` — nada no registro, nada em Program Files, remoção = deletar a pasta.
- Incidente: primeiro download do `.zip` veio corrompido/incompleto (182MB de 327MB esperados, hash não bateu). Resolvido rebaixando com `Invoke-WebRequest -UseBasicParsing` e validando hash SHA-256 antes de extrair.
- **Limitação confirmada:** sem sandbox de SO — o app roda com as mesmas permissões do usuário Windows; a contenção é comportamental (só abrir pastas que você escolher dentro do app), não garantida tecnicamente.
- Caso de uso real identificado: gerar landing pages (`web-prototype`, `saas-landing`) com handoff direto pra código real (HTML/CSS), útil pro `nossocrm` ou site institucional — mais relevante que a parte de imagem/post (já cobertra pelo `instagram-content-cloner`).

### Teste do Remotion (`npx create-video@latest`) — geração de vídeo com legendas
- Projeto scaffolded em `Documentos\teste-remotion\meu-teste\` com template **TikTok** (legendas animadas palavra-por-palavra via Whisper.cpp local).
- Licença Remotion: grátis pra indivíduos/empresas até 3 funcionários (Lucas se qualifica).
- **Descoberta importante sobre a máquina:** só 7,7GB de RAM total, frequentemente <1GB livre. Modelo Whisper `medium` falhou por falta de memória (`failed to allocate buffer of size 1533143072`). Resolvido trocando pra modelo `base` (~500MB) + idioma `pt` — transcrição funcionou (confiança >0,99).
- Verificado funcionando ponta a ponta via Chrome com remote debugging (MCP chrome-devtools): Studio sobe sem erros, 4 blocos `<Sequence>` confirmam que as legendas são lidas e renderizadas corretamente.
- **Regra geral pra IA local daqui pra frente:** com 7,7GB de RAM, sempre preferir variantes `tiny`/`base`/`small` de qualquer modelo (nunca `medium`/`large`) e fechar apps pesados antes de rodar.

### Incidente operacional — lição aprendida
- Um `taskkill /F /IM chrome.exe` fechou **todas** as instâncias do Chrome no sistema (24 processos), não só a instância de debug isolada que era o objetivo. Corrigido nas tentativas seguintes filtrando por `CommandLine -like "*chrome-debug-profile*"` antes de matar processo — nunca mais usar `taskkill` por nome de imagem genérico quando o objetivo é fechar só um processo específico.
